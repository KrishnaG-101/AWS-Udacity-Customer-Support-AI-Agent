================================================================================
PROJECT REFLECTION: AI CUSTOMER SUPPORT AGENT
================================================================================

1. Architectural Design Decision
A foundational implementation choice in this project was adding backend tools using the Amazon Bedrock AgentCore Gateway using the Model Context Protocol (MCP). Rather than hardcoding HTTP client wrappers or tightly coupling REST endpoints and AWS Lambda functions inside the code, the AgentCore Gateway acts as a centralized bridge connecting both API Gateway routes (order_tracker) and standalone Lambda functions (refund_processor) over a HTTP protocol. This enables independent and modular working of components, easy scalability of business services, centralizes tool-level governance and authentication, and simplifies the agent's tool surface to a clean and declarative MCP client.

2. Concrete Challenge & Resolution
During development, a critical challenge arose during the cloud deployment of the browser automation tool (AgentCoreBrowser). As I was using the Direct Code Deployment option in the AgentCore configuration, packaging dependencies from a Windows development environment caused the archive (dependencies.zip) to omit Linux based execution bits (0o755). When unpacked into the cloud Linux container runtime, the Playwright Node.js driver binary was marked read-only, triggering "PermissionError: [Errno 13] Permission denied...". Modifying permissions in-place failed because the particular directory was mounted read-only. I resolved this by implementing an initialization code in main.py that executes during container bootstrap: it copies the Node binary into the writable, executable /tmp partition, applies chmod 0o755, and exports the PLAYWRIGHT_NODEJS_PATH environment variable. This allowed Playwright to successfully launch its driver process over the cloud based container without modifying packaging tooling.

3. Production Consideration
In a production deployment, managing conversation context and token budgets is critical. As multi-turn conversational sessions grow, adding raw long-term memory context alongside conversation histories will eventually surpass model context limits and increase latency and costs. To address this, I would implement an automated summarization hook that activates when session message history exceeds a threshold (e.g., 10 turns). Older conversations would be condensed into structured summaries while keeping recent context intact. Combined with semantic caching of repeated or similar queries and least-privilege IAM scoping on tool execution roles, this ensures the agent remains cost-effective and resilient at enterprise scale.
